Người 1 · FTP

Sniffing plaintext & credential theft
01
📚 Nền tảng

Nguyên lý FTP & nền móng mạng

Hiểu control/data channel, active vs passive, vì sao FTP lộ plaintext — trước khi bấm bất kỳ lệnh nào.

📄FTP Overview — cổng, kênh, phiên làm việcoverview 🌐Network Basics — TCP/IP, socket, DNS/MXfundamentals
🔴 Tấn công

Sniff FTP credentials & data

Dùng Wireshark/tcpdump bắt gói tin FTP plaintext trong lab. Trích xuất username, password và nội dung file truyền đi. Chứng minh FTP gửi mọi thứ dưới dạng cleartext.

  • File .pcapng chứa phiên FTP đầy đủ
  • Ảnh Wireshark hiển thị USER/PASS/command
  • Bảng thông tin nhạy cảm bị lộ
⚔️FTP Attack Surface — cleartext, anon, misconfigattack 🦈Network Analysis — Wireshark, tcpdump, filtertools
🟢 Phòng thủ

Chuyển sang FTPS hoặc SFTP

Bật TLS trên vsftpd (explicit FTPS) hoặc chuyển hẳn sang SFTP. So sánh cùng thao tác trước/sau: Wireshark không còn đọc được nội dung.

  • Cấu hình vsftpd trước và sau
  • PCAP "sau" chứng minh dữ liệu đã mã hóa
  • Test login thành công qua FTPS
🛡️FTP Defense — TLS, chroot, quyền tối thiểudefense
🟣 Điều tra

Phân tích forensic trên PCAP

Dựng timeline sự kiện từ capture: kết nối → login → lệnh → truyền file → ngắt. Xác định thời điểm credential bị lộ, trích xuất file bằng Wireshark Export Objects. Viết báo cáo: Ai? Khi nào? Dữ liệu nào bị rò rỉ?

Người 2 · FTPS

TLS misconfiguration & downgrade attack
02
📚 Nền tảng

TLS / chứng thư số & nguyên lý FTP

FTPS = FTP + TLS: phải nắm TLS handshake, cipher suite, CA/self-signed trước, rồi mới tới cấu hình vsftpd.

🔐TLS Fundamentals — handshake, cipher, X.509, CAfundamentals 📄FTP Overview — nền giao thức FTP/FTPSoverview
🔴 Tấn công

TLS downgrade / cert validation bypass

Cấu hình FTPS sai trong lab: cho phép fallback plaintext, cipher yếu, self-signed cert không verify. Demo client kết nối "FTPS" nhưng thực tế vẫn truyền plaintext.

  • Transcript kết nối "FTPS giả" vẫn đọc được dữ liệu
  • Output openssl s_client hiện cipher yếu
  • Ảnh cảnh báo certificate bị bỏ qua
⚔️FTP Attack Surface — mục cleartext & downgradeattack 🔐TLS Fundamentals — phần cipher/protocol yếufundamentals
🟢 Phòng thủ

Hardening TLS configuration

Cấu hình vsftpd: chỉ TLS ≥ 1.2, tắt cipher yếu, bật verify cert. Test: client không thể connect nếu không dùng TLS mạnh.

  • Cấu hình TLS hardened
  • nmap ssl-enum-ciphers xác nhận chỉ cipher mạnh
  • Kết nối thất bại khi cố downgrade
🛡️FTP Defense — bắt buộc TLS, tắt anondefense 🔐TLS Fundamentals — cấu hình cipher an toànfundamentals
🟣 Điều tra

Audit log TLS negotiation failures

Phân tích vsftpd.log: tìm "SSL connection failed", đếm negotiate thất bại theo IP/thời gian. Xây dựng biểu đồ tần suất → phát hiện pattern tấn công downgrade. Viết timeline incident.

Người 3 · SFTP / SSH

Brute-force & key-based hardening
03
📚 Nền tảng

SSH transport, host key, subsystem SFTP

Hiểu vì sao SFTP không phải "FTP + SSL": một kênh TCP:22 duy nhất, subsystem sftp, key authentication.

📄SFTP / SSH Overviewoverview 🌐Network Basics — socket, firewall, NATfundamentals
🔴 Tấn công

SSH brute-force trên lab

Dùng Hydra/Medusa (chỉ trên VM lab!) thử dictionary attack vào SSH user yếu. Ghi nhận số lần thử, thời gian crack. Demo weak password bị chiếm trong vài giây.

  • Log brute-force: attempts, thời gian, kết quả
  • Auth.log chụp failed passwords liên tiếp
  • Screenshot tool tấn công (blur sensitive info)
⚔️SFTP / SSH Attack Resourcesattack
🟢 Phòng thủ

Key-only auth + chroot + Fail2ban

Tắt password auth, bật Ed25519 key-only, chroot jail cho SFTP user, cài Fail2ban ban IP sau N lần fail. Test: key hợp lệ vẫn vào, brute-force bị ban.

  • sshd_config trước/sau
  • Fail2ban status + jail config
  • Retest: legitimate OK, attack blocked
🛡️SSH / SFTP Hardeningdefense
🟣 Điều tra

Forensic analysis trên auth.log

Trích xuất failed attempts, group by source IP, tính frequency/timing. Xác định top offending IPs, username bị nhắm nhiều nhất. So sánh trước/sau Fail2ban: attempts giảm bao nhiêu %. Viết incident report.

Open relay abuse & spam prevention
04
📚 Nền tảng

Luồng thư, MUA/MSA/MTA, cổng 25/587/465

Phân biệt server-server vs client-server, vì sao submission phải tách khỏi port 25, DNS MX hoạt động ra sao.

📄SMTP Overview — EHLO, MAIL FROM, RCPT TO, DATAoverview 🌐Network Basics — DNS/MX, socket, portfundamentals
🔴 Tấn công

Exploit open relay (lab isolated)

Cấu hình Postfix sai: mynetworks quá rộng, thiếu smtpd_recipient_restrictions. Từ máy khác trong lab gửi mail đến domain ngoài → server chấp nhận relay.

  • Transcript SMTP relay thành công (250 OK)
  • mail.log showing relay abuse
  • Sơ đồ luồng mail bị exploit
⚔️SMTP Attack Surface — open relay, spoofingattack
🟢 Phòng thủ

Close relay + enforce AUTH/TLS on 587

Thu hẹp mynetworks, bật reject_unauth_destination, yêu cầu SASL auth trên 587, bật STARTTLS. Retest: relay ngoài bị reject (554).

  • main.cf trước/sau
  • Transcript 554 Relay access denied
  • Gửi mail nội bộ TLS+AUTH thành công
🛡️SMTP Defense — relay restriction, SPF/DKIM/DMARCdefense 🔐TLS Fundamentals — STARTTLS trên 587fundamentals

Mail queue forensics & log correlation

Truy vết queue ID của mail relay trái phép, xác định nguồn IP, timestamp, recipient list. Đếm volume bất thường/giờ. Correlate với auth.log. Xây dựng timeline cuộc tấn công relay.

Người 4 · POP3 / IMAP

Plaintext auth & mailbox exfiltration
04+
📚 Nền tảng

POP3 vs IMAP: mailbox ở đâu, đồng bộ thế nào

POP3 thiên về tải thư về máy; IMAP giữ trạng thái/folder trên server. Cả hai đều cần TLS bắt buộc.

📄POP3 Overview — RETR, DELE, mailbox tải vềoverview 📄IMAP Overview — SELECT, FETCH, folder serveroverview
🔴 Tấn công

Sniff POP3/IMAP credentials & pull mailbox

Kết nối POP3 (110) / IMAP (143) plaintext. Bắt gói → trích xuất user/pass. Dùng credential kéo toàn bộ mailbox về máy attacker (data exfiltration).

  • PCAP chứa POP3/IMAP plaintext session
  • Ảnh captured credentials
  • Screenshot mailbox bị exfiltrate
⚔️POP3 Attack Surfaceattack ⚔️IMAP Attack Surfaceattack
🟢 Phòng thủ

Enforce POP3S/IMAPS + disable plaintext

Dovecot: ssl=required, disable_plaintext_auth=yes, cấu hình TLS cert. Test: plaintext bị reject, IMAPS/POP3S hoạt động bình thường.

  • doveconf output before/after
  • openssl s_client test on 993/995
  • Plaintext connection rejected log
🛡️POP3 Defense — 995, ssl=requireddefense 🛡️IMAP Defense — 993, tắt plaintext authdefense
🟣 Điều tra

Detect mailbox exfiltration via logs

Tìm sessions login từ IP lạ, đếm FETCH/RETR commands bất thường (volume spike). Phát hiện "kéo sạch mailbox": nhiều RETR liên tiếp + logout ngay. Timeline: credential lộ → mailbox exfiltrate → bao nhiêu mail bị lấy.
